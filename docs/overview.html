security-kit（仮称） / 設計と試作の段階

AI開発セキュリティ支援キット

Claude Code などで開発するときに、セキュリティに強い先輩のように「そこ危ないよ」と声をかけ、理由と直し方を伝えるキットです。重大な事故だけはその場で止め、ルールは YAML 一か所で管理します。

先輩の声かけの例
「その API キー、ファイルに直接書くと GitHub に上がった時点で使われてしまうよ。環境変数から読む形にしておこう」
25ルール（うち 22 が有効）
5自動で動くタイミング
3利用者が呼べるコマンド
1ルールを書く場所（YAML）

いつ、何をするか

利用者が何も呼ばなくても、作業の流れに合わせて自動で動きます。

  1. 書く前

    秘密情報を止める

    API キーなどを書こうとしたら、書き込みを止めます。

  2. 書いた直後

    危ない書き方を伝える

    見つけたらすぐ Claude に伝えます。Python は Ruff、ほかの言語は独自の簡易チェックです。

  3. 作業の区切り

    直ったかを確かめる

    伝えた警告が直ったかを見て、このターンのまとめを表示します。

  4. 作業の区切り背景で実行

    AI がレビューする

    このターンの変更を AI が見て、重大な指摘があれば Claude を呼び戻します。

  5. コミットの直後背景で実行

    関係するファイルまで見る

    コミットされた変更を、AI が関係するファイルもたどってレビューします。

呼べるコマンド

コマンドすること
/security-kit:initプロジェクトに設定を置きます。.env などの読み取り禁止、キットの有効化、公式プラグインを止める指定、CLAUDE.md・AGENTS.md への追記です。書き込む前に予定と差分を見せて確認します。
/security-kit:consult「これ大丈夫？」の相談です。ファイルは書き換えず、自社のルールに沿って答えます。ファイルやルール ID を書かなければ、今の変更を見ます。
/security-kit:report誤った指摘、ルールの提案、使いにくさを、このリポジトリの Issue にします。登録の前に下書きを見せて確認します。

指摘の強さは3段階

止める

秘密情報の漏えいなど、重大な事故につながるもの。その場で書き込みを止めます。

警告

危ない書き方。理由と直し方を伝え、作業の区切りで直ったかを確かめます。

助言

気をつけたい点。伝えるだけで、作業は止めません。

指摘は、今回の変更に絞ります。以前からある問題は伝えないので、既存のプロジェクトにも入れてすぐ使えます。

ルール一覧

元データは rules/R-NNN.yaml です。「準備中」は、設定や運用で守る前提で、キット側の自動検出がまだないものです。

    ルールは YAML で一元管理

    人が編集するのは rules/ の YAML だけです。ビルドスクリプトが、フックが読むデータや説明などを作り直します。

    rules/R-NNN.yaml人が編集
    →
    build/build.py検査して生成
    →
    data/rules.jsonフックが読む
    skills/senpai/rules/先輩の説明
    docs/rules.csvExcel で閲覧
    • ルールに書いた違反例と正常例が、そのままテストになります。
    • 生成されたファイルは手で編集しません。build.py --check でずれを確かめます。
    • 各ルールには、何が危ないか、なぜ危ないか、どう直すか、根拠（CWE など）、担当者、最終見直し日を書きます。

    プロジェクトごとの設定

    .claude/security-kit.json で動かし方を変えられます。/security-kit:init は、まず警告モードで作ります。

    {
  "mode": "warn",
  "exclude": ["tests/fixtures/*"],
  "ai_review": {
    "stop": true,
    "commit": true,
    "model": "sonnet",
    "max_per_session": 20
  }
}

    指摘が当てはまらないとき

    その行に印と理由を書くと除外できます。印の追加は PR でレビューします。

    指摘の種類印
    秘密情報gitleaks:allow
    Ruff（Python）# noqa: 番号
    簡易チェック・AI レビューsecurity-kit:allow

    案件だけの決まりは .claude/security-kit-guidance.md に書くと、AI レビューが読みます。

    試し方

    必要なもの

    • Python 3、git（必須）
    • Ruff：Python の書いた直後の検査
    • gitleaks：作業の区切りの秘密情報の検査
    • Claude Code へのサインイン：AI レビュー

    Ruff、gitleaks、サインインは無くても動きます。その検査だけ飛ばします。

    インストールせずに読み込む

    claude --plugin-dir /path/to/security-kit/plugins/security-kit

    テストを実行する

    python3 -m unittest discover -s tests -v

    Anthropic 公式の security-guidance プラグインと同じ役割を、このキットだけで受け持ちます。二重に注意が出ないよう、init がそのプロジェクトだけ公式プラグインを止めます。コードは流用していません。
