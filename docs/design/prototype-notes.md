## 4. 分かったことと、決めたこと

| 分かったこと | 決めたこと |
|---|---|
| **gitleaks は起動だけで約1秒かかる。** 正規表現のエンジンの初期化に時間がかかる作りのためで、検査する量を減らしても、ルールを絞っても変わらなかった | 書く前の検査では gitleaks を使わず、キット内蔵の判定にする。gitleaks は、作業の区切り・コミット前・PR 時で使う |
| 内蔵の判定は、決まった書き出しを持つ鍵（AWS、GitHub、各種 AI サービスなど16種類）と秘密鍵のブロックを見分けられる。gitleaks の約200種類よりは少ない | 書く前に止めるのは「形だけで秘密情報とわかるもの」に限る。それ以外は gitleaks が後の段階で見つける |
| Ruff の「パスワードの直書き」（S105 など）は、変数の名前からの当て推量である | 「止める」の R-001 には対応付けず、「警告」の別のルールにする |
| Ruff の説明文には、変数の名前などコードの中身が入ることがある | 通知文には Ruff の説明文を使わず、番号と行だけを使う（NFR-13） |

| 同じタイミングのフックは並んで動く。ほかのプラグインのフックとも同時に動く | 状態のファイルは、鍵をかけてから読み書きする |

## 5. 実際の Claude Code での動き

### 5.1 秘密情報を書かせた場合（止める）

- 書き込みは止まり、ファイルは作られなかった。
- Claude は、止められた理由（R-001）を利用者に説明し、3つの進め方（印を付ける、環境変数から読む、利用者が自分で書く）を示した。
- Claude は、除外の印を自分の判断では付けなかった。「印は PR でレビューされる前提の仕組みなので、自分の判断でスキャナを回避しない」と説明した。

設計どおりの動きである。

### 5.2 危ない書き方を自然に書いた場合（警告）

テーブル名と列名を受け取って SQL を組み立てる関数を書かせた。

- 書いた直後に、警告（R-012、該当の行番号つき）が Claude に届いた。
- Claude はコードを直した（テーブルと列が実在するかを確かめる処理を足した）。
- Claude は最後に「ひとこと：」の形で、理由と直し方を利用者に説明した。

**設計と違った点**：説明は出たが、順番は「直してから説明」だった。要件（FR-12）は「説明してから直す」である。

### 5.3 利用者が危ない書き方をはっきり指定した場合（警告）

「f 文字列で値を埋め込んで」と指定して書かせた。

- 警告は届いた。Claude は危険性と安全な書き方を説明したが、利用者の指定を優先してコードは変えなかった。
- 「変更が必要なら指示してください」と利用者に判断を委ねた。

「警告」は止めないレベルなので、利用者の判断に委ねる動きは方針に合っている。

## 6. 公式の security-guidance プラグインとの重なり

試作の途中で、この PC に Anthropic 公式の `security-guidance` プラグイン（2.0.20）が入っていて、キットと同じタイミングで動いていることが分かった。

| 公式プラグインの機能 | 中身 | キットで重なる部分 |
|---|---|---|
| 書いた直後の注意 | 約25種類の危ない書き方を正規表現で見つけて注意する | ② 書いた直後の検査 |
| 作業の区切りの AI レビュー | 変更の差分を AI に送り、重大な指摘を Claude に戻す | ③ 作業の区切りの検査 |
| コミット時の AI レビュー | 関係するファイルを AI がたどって読み、複数のファイルにまたがる欠陥（認可の漏れなど）を探す | キットには無い |
| 組織ごとのルール | `.claude/claude-security-guidance.md` に書いたルールを、AI レビューに読ませる | ルールの配布 |

**キットにしか無いもの**

- 秘密情報を書く前に止める（公式プラグインは注意するだけ）
- ルール ID と、初心者向けの日本語の説明の型
- 今回変えた行だけに絞ること、記録と集計（証跡）
- 強制設定、パッケージの確認、PR 時の検査（AI ではない検査ツールと別ベンダーの AI）

**気をつける点**

- 両方を入れると、同じ書き込みに2つの注意が出る。試作中にも、ルールの説明文に書いた「verify=False」という文字に公式プラグインが反応した（文章であって、コードではない）。
- 公式プラグインの AI レビューは、同じベンダーの AI による確認である。キットの「独立性の原則」では自己チェック（層3）にあたり、最終判定には使えない。
- AI レビューは、作業の区切りのたびに利用量を使う。変更の差分が Anthropic に送られる。

**案（この時点。その後、案2に決定した。9章を参照）**

1. 公式プラグインを活かし、キットは重ならない部分に集中する。
   - コミット時の AI レビューは、キットが弱い「認可の漏れ」（脅威モデル T-23）を補えるので、そのまま使う。
   - 作業の区切りの AI レビューも公式に任せる。キットの③は、gitleaks と Semgrep の検査と、作業のまとめだけにする。
   - 書いた直後の注意は重なるので、公式の側を止める（設定で止められる）。キットの②は、行の絞り込みと日本語の説明があるため残す。
   - build.py で、自社のルールから `.claude/claude-security-guidance.md` も生成し、公式の AI レビューに自社のルールを読ませる。
2. 公式プラグインは使わず、キットだけで作る。

案1の方が作る量が減り、「標準に乗り、差分だけ持つ」という方針にも合う。利用量とデータの送信先を確認したうえで決める。

## 9. 2回目の試作：作業の区切りの検査と AI レビュー（2026-11-13）

### 9.1 方針の決定

公式の security-guidance プラグインには頼らず、同じ役割をキットだけで受け持つことにした（利用者の判断）。公式プラグイン（Apache-2.0）の作りを読み、考え方を参考にして作った。コードは流用していない。

**公式プラグインから学んだこと**

| 学んだこと | キットでの扱い |
|---|---|
| AI レビューは背景で動かし、指摘があったときだけ Claude を呼び戻す | 同じ仕組み（asyncRewake）を使う |
| ターンの始めに状態を記録し、そのターンの差分だけをレビューする | 同じ考え方を取り入れた。書いた直後の検査の「変えた行への絞り込み」にも使う |
| レビュー役は、設定なし・読むだけの道具で起動する | Claude Code の「制限つき」の起動を使う |
| 差分の中の秘密情報らしき部分は、AI に送らない | 伏せ字にしてから送る |
| 利用者がはっきり指定した書き方で、危険性を伝えてあるなら、変えなくてよい | 通知文にそう書く |
| 約25種類の危ない書き方の一覧 | Python は Ruff に任せ、JavaScript・Go・GitHub Actions・HTML の分を独自の簡易チェックにした |

**キットで変えたこと**

| 公式プラグイン | キット |
|---|---|
| 利用者のサインイン情報を受け取って AI を呼ぶ | サインイン情報に触れない。利用者の Claude Code をもう1つ起動して使う |
| AI が書いた文章を、そのまま Claude に渡す | 決めた形だけを受け取り、自社のルールの文章で伝える。AI のメモは短く切り、記号と URL を取り除く |
| レビュー用の追加の部品を、自動で PC に入れる | 追加で入れるものは無い |
| 文書のファイルにも反応することがある | コードのファイルだけを見る |

### 9.3 確かめたことと結果

| 確かめたこと | 方法 | 結果 |
|---|---|---|
| フック全体のふるまい | テスト46件。AI レビューは、決まった返事をする代役で確かめた | すべて成功 |
| 作業のまとめの表示 | 実際の Claude Code | 助言2件のまとめが出た |
| 作業の区切りの AI レビュー | 実際の Claude Code。持ち主の確認が無い削除の処理を書かせた | 「認可の漏れ」（R-021）を指摘した。Claude は「ひとこと：」の形で利用者に説明した |
| コミットの直後の AI レビュー | 本物のレビュー役。持ち主を確かめる関数が別のファイルにあり、新しい処理だけがそれを使っていない形にした | 別のファイルの関数まで読んだうえで、「認可の漏れ」を指摘した |
| 信頼できない返事の扱い | 代役に、差分に無いファイル、決めていない分類、URL 入りのメモを返させた | すべて受け取らなかった |
| 秘密情報を AI に送らないこと | 鍵の形の文字列を含む差分をレビューさせた | 伏せ字になって送られた |

検査ツールでは見つからない「認可の漏れ」（脅威モデル T-23）を、AI レビューが2回とも見つけた。

### 9.4 時間と費用の目安

小さな差分を haiku でレビューした場合の実測である。

| 測ったもの | 時間 | 費用の目安 |
|---|---|---|
| 作業の区切りの AI レビュー | 約 6 秒 | 約 0.002 ドル |
| コミットの直後の AI レビュー（ファイルをたどる） | 約 11 秒 | 約 0.003 ドル |
| 実際の Claude Code での1回の依頼の全体（書く、レビュー、説明） | 約 40 秒 | |

- 個人向けの契約では、費用ではなく利用量の枠から引かれる。
- 既定のモデルは sonnet にしてある。haiku より時間と利用量がかかる。大きな差分や sonnet での実測は、まだ行っていない。
