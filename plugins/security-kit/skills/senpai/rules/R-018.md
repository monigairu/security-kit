# R-018 パスワードらしき値の直書き

| 項目 | 内容 |
|---|---|
| 重大度 | 警告 |
| 領域 | 秘密情報 |
| 根拠 | CWE-259 パスワードの直書き、CWE-798 認証情報の直書き |

## 伝え方

- 何が危ないか: パスワードや鍵のような名前の変数に、値を直接書いている
- なぜ危ないか: 本物の値だった場合、ファイルが共有されたときに漏れる
- どう直すか: 本物なら環境変数などから読み込む。ダミーの値なら、その行に除外の印（# noqa と理由）を付ける

## 違反例（指摘される書き方）

`app/settings.py`

```python
DB_PASSWORD = "s3cr3t-value"
```

`app/db.py`

```python
def connect(lib):
    return lib.connect(host="db", password="s3cr3t-value")
```

## 正常例（安全な書き方）

`app/settings.py`

```python
import os

DB_PASSWORD = os.environ["DB_PASSWORD"]
```

## 見つけ方

- Ruff（書いた直後。Python）: S105、S106、S107
- AI レビュー（作業の区切り・コミットの直後）: 分類 `hardcoded-secret`

## 当てはまらないとき

- Ruff の指摘: その行に `# noqa: S105` と理由を書く（番号は指摘されたもの）
- 簡易チェック・AI レビューの指摘: その行に `security-kit:allow` と理由を書く
- 印は、利用者が当てはまらないと判断したときだけ付ける。AI が自分の判断で付けてはいけない。印の追加は PR でレビューされる。
- ルールそのものを一時的に外すときは、プロジェクトの `.claude/security-kit.json` に期限つきの例外を書き、PR で承認を受ける。
