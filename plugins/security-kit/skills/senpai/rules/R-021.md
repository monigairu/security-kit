# R-021 認可の漏れ

| 項目 | 内容 |
|---|---|
| 重大度 | 警告 |
| 領域 | API |
| 根拠 | CWE-639 利用者が指定するキーによる認可の回避、CWE-862 認可の欠如、OWASP Top 10:2025 A01 アクセス制御の不備 |

## 伝え方

- 何が危ないか: ほかの利用者のデータを読み書きできる処理になっている可能性がある
- なぜ危ないか: ID を変えるだけで、他人のデータを見られたり書き換えられたりする
- どう直すか: 処理の中で、ログイン中の利用者がそのデータの持ち主（または権限のある人）かを確認する。他人のデータにアクセスできないことを確かめるテストを書く

## 違反例（指摘される書き方）

`app/orders.py`：ログインは確かめているが、注文の持ち主かを確かめていない

```python
@app.get("/orders/{order_id}")
def get_order(order_id: int, user: User = Depends(current_user)):
    return db.get_order(order_id)
```

## 正常例（安全な書き方）

`app/orders.py`

```python
@app.get("/orders/{order_id}")
def get_order(order_id: int, user: User = Depends(current_user)):
    order = db.get_order(order_id)
    if order is None or order.owner_id != user.id:
        raise HTTPException(status_code=404)
    return order
```

## 当てはまらないとき

- 簡易チェック・AI レビューの指摘: その行に `security-kit:allow` と理由を書く
- 印は、利用者が当てはまらないと判断したときだけ付ける。AI が自分の判断で付けてはいけない。印の追加は PR でレビューされる。
- ルールそのものを一時的に外すときは、プロジェクトの `.claude/security-kit.json` に期限つきの例外を書き、PR で承認を受ける。
