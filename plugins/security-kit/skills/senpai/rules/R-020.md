# R-020 認可の確認

| 項目 | 内容 |
|---|---|
| 重大度 | 助言 |
| 領域 | API |
| 根拠 | CWE-862 認可の欠如、OWASP Top 10:2025 A01 アクセス制御の不備 |

## 伝え方

- 何が危ないか: API の入口を書いた。誰がアクセスできるかを確認する必要がある
- なぜ危ないか: 確認が漏れると、他人のデータを見られたり書き換えられたりする
- どう直すか: ログイン済みか、本人のデータかを確認する処理を入れ、他人のデータにアクセスできないことを確かめるテストを書く

## 違反例（指摘される書き方）

`app/api.py`

```python
@app.get("/users/{user_id}")
def get_user(user_id: int):
    return db.get_user(user_id)
```

`web/api.js`

```javascript
app.get("/users/:id", async (req, res) => {
  res.json(await db.getUser(req.params.id));
});
```

## 正常例（安全な書き方）

`app/settings.py`：API の入口ではない処理には反応しない

```python
import functools

@functools.cache
def load_settings():
    return {}
```

`web/app.js`

```javascript
app.use(express.json());
```

> API の入口を書くと、認可の確認を書いた場合も助言が出る。確認があるかどうかまでは見分けない

## 見つけ方

- キット独自の簡易チェック K-001（書いた直後。対象: `*.py`）
- キット独自の簡易チェック K-002（書いた直後。対象: `*.js`、`*.jsx`、`*.ts`、`*.tsx`、`*.mjs`、`*.cjs`、`*.mts`、`*.cts`、`*.vue`、`*.svelte`）

## 当てはまらないとき

- 簡易チェック・AI レビューの指摘: その行に `security-kit:allow` と理由を書く
- 印は、利用者が当てはまらないと判断したときだけ付ける。AI が自分の判断で付けてはいけない。印の追加は PR でレビューされる。
- ルールそのものを一時的に外すときは、プロジェクトの `.claude/security-kit.json` に期限つきの例外を書き、PR で承認を受ける。
