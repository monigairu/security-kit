# R-001 秘密情報をコードに直接書かない

| 項目 | 内容 |
|---|---|
| 重大度 | 止める |
| 領域 | 秘密情報 |
| 根拠 | CWE-798 認証情報の直書き、要件定義書 11章 R-001 |

## 伝え方

- 何が危ないか: API キーやパスワードなどの秘密情報を、ファイルに直接書こうとしている
- なぜ危ないか: ファイルが共有されたり GitHub に上がったりすると、その鍵で不正に利用される
- どう直すか: 値は環境変数や秘密情報の管理の仕組みから読み込み、ファイルには書かない

## 正常例（安全な書き方）

`app/config.py`：環境変数から読み込む

```python
import os

OPENAI_API_KEY = os.environ["OPENAI_API_KEY"]
```

> 違反例は、ファイルに完成形の鍵を書けないため、tests/hooks/test_hooks.py で実行時に組み立てて確かめる

## 見つけ方

- キット内蔵の判定（書く前。形だけで秘密情報とわかるもの 16 種類）
- gitleaks（作業の区切り・コミット前・PR 時）: 全ルール

## 当てはまらないとき

- 秘密情報の指摘: その行に `gitleaks:allow` と理由を書く。まとめて外すものは `.gitleaks.toml` に書く
- 印は、利用者が当てはまらないと判断したときだけ付ける。AI が自分の判断で付けてはいけない。印の追加は PR でレビューされる。
- ルールそのものを一時的に外すときは、プロジェクトの `.claude/security-kit.json` に期限つきの例外を書き、PR で承認を受ける。
