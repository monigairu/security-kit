# security-kit への報告

報告の内容: $ARGUMENTS

キットのリポジトリは全案件で共有する。Issue に入れてよいのは、ルール ID、検査ツールの番号、ファイルの種類（拡張子）、場面、キットの版、利用者の説明だけ。

## 手順

1. 情報を集める。

   ```
   python3 -I -S "${CLAUDE_PLUGIN_ROOT}/scripts/report.py" "${CLAUDE_SESSION_ID}"
   ```

2. 報告の種類を、「誤った指摘」「ルールの提案」「使いにくい（遅い・邪魔など）」から決める。引数と会話から決められなければ、利用者に聞く。
3. 誤った指摘のときは、対象の指摘を1の一覧から選ぶ。どれか分からなければ、番号で利用者に聞く。
4. 下の形で下書きを作る。
5. 下書きを点検し、次のものが入っていたら消す。
   - コード、ファイルの場所（ファイル名を含む）、秘密情報
   - プロジェクト名、顧客名、案件名、人の名前
   - 患者や利用者のデータ
6. 下書きを利用者に見せ、「この内容で登録してよいですか？」と確かめる。はっきり了承されるまで登録しない。
7. 了承されたら登録する。本文は標準入力で渡す。

   ```
   gh issue create --repo <1で表示された指定> --title "<題名>" --body-file -
   ```

8. 登録された Issue の URL を伝える。gh が無い・ログインしていないときは、下書きをそのまま表示し、GitHub の画面から登録する方法を伝える。

## 下書きの形

題名：`[誤検知] R-012 SQL インジェクション（.py）`、`[提案] 〜`、`[使いにくい] 〜`

本文：

```
## 種類
誤った指摘

## 対象
- ルール: R-012 SQL インジェクション
- 検査ツールの番号: ruff S608
- ファイルの種類: .py
- 場面: 書いた直後
- キットの版: 0.1.0

## 内容
何が起きたか、なぜ誤りだと思うか、どうなってほしいかを、コードを貼らずに言葉で書く。
```
