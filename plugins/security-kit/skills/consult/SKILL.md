# セキュリティの相談

相談の対象: $ARGUMENTS

ファイルは書き換えない。直すかどうかは利用者が決める。

## 手順

1. 対象を決める。
   - ルール ID（R-012 など）だけのとき：`${CLAUDE_PLUGIN_ROOT}/skills/senpai/rules/<ルール ID>.md` を読み、下の「答え方」の型で説明して終わる。
   - ファイルやフォルダのとき：その場所を対象にする。
   - 処理の説明（「このログイン処理」など）のとき：Grep と Glob で該当するファイルを探す。候補が複数あれば、利用者に確かめる。
   - 何も無いとき：まだコミットしていない変更を対象にする。
2. 検査スクリプトを実行する。今の変更が対象なら、ファイルを付けずに実行する。

   ```
   python3 -I -S "${CLAUDE_PLUGIN_ROOT}/scripts/consult.py" [ファイルやフォルダ ...]
   ```

3. 結果に出たルールの説明（「説明:」の場所）を読む。
4. 対象のコードを読み、検査ツールでは見つからない点を確かめる。
   - 認可：`${CLAUDE_PLUGIN_ROOT}/skills/senpai/authz.md` に沿って確かめる。
   - 入力の流れ：外から来た値が、SQL 文、コマンド、ファイルの場所、通信の宛先、HTML に、確かめられずに届いていないか。
   - 当てはまるルールは、一覧 `${CLAUDE_PLUGIN_ROOT}/skills/senpai/rules/index.md` から探して説明を読む。
5. 下の「答え方」で答える。

## 答え方

- 最初に結論を、「大丈夫」「気になる点あり」「直した方がよい」のどれか1つで示す。
- 指摘ごとに、場所、何が危ないか、なぜ危ないか、どう直すか、ルール ID を書く。初心者にもわかる言葉で短く書く。
- 検査ツールの指摘と、コードを読んで気づいた点を分けて書く。気づいた点には、どのくらい確かかも添える。
- 最後に「直しましょうか？」と聞く。直すのは利用者の返事を待ってから。
- 誤検知だと思う指摘は、根拠を示して、報告コマンド `/security-kit:report` を案内する。
- 例のコードに、秘密情報（それらしい値も含む）を書かない。
